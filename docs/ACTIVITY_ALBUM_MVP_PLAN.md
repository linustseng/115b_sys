# 115B Sys｜活動相簿 MVP 規劃

## 1. 目標與範圍

把 115B Sys 做成班級的私有活動照片庫：同學能在手機一次上傳多張照片，班內成員可以快速瀏覽、查找與下載；管理員能管理相簿與內容。

第一期的完成標準：使用者登入後，可在 30 秒內建立或進入活動相簿、從手機一次選取多張照片上傳，並在手機友善的照片牆查看。

## 2. 第一期決定

| 項目 | 決定 |
| --- | --- |
| 可查看者 | 僅 115B Sys 已登入同學 |
| 可上傳者 | 所有已登入同學 |
| 可管理／刪除者 | 管理員 |
| 支援格式 | JPG、PNG、HEIC／HEIF |
| 單檔上限 | 15 MB |
| 影片 | 不在第一期 |
| 儲存位置 | Supabase Storage 私有 bucket |
| 上傳路徑 | 瀏覽器取得短效 signed upload URL 後直傳 Supabase；不經 Render 搬檔 |
| Drive／Google Photos | 不在第一期；Google Drive 多選匯入列為第二期 |

## 3. 第一期間功能

### 同學端

1. 活動相簿列表：相簿封面、名稱、日期、地點、照片數、最新照片。
2. 相簿瀏覽：手機優先的照片瀑布流，依最新上傳排序。
3. 照片檢視：點擊後全螢幕檢視、左右切換、縮放、下載。
4. 大量上傳：手機多選、桌面拖拉；可看總進度、單張狀態與失敗重試。
5. 查找：依相簿名稱搜尋；相簿內依日期／上傳者篩選。

### 管理端

1. 建立、編輯、封存活動相簿。
2. 設定封面、名稱、活動日期、地點與說明。
3. 隱藏／還原／刪除照片；檢視上傳者與上傳時間。
4. 管理頁可切換「進行中」「已結束／封存」相簿。

## 4. 非第一期範圍

- 影片上傳與轉檔
- Google Drive／Google Photos 匯入
- 對外公開分享連結
- AI 人臉辨識、人物搜尋與自動分類
- 留言、按讚、共同編輯
- 對原始照片進行永久刪除前的保留／申訴流程

## 5. 資料與技術設計

新增獨立資料模型，不混入現有一般 `attachments` 的文件／報帳用途：

- `activity_albums`：id、title、description、event_date、location、cover_photo_id、status、created_by、created_at、updated_at
- `activity_photos`：id、album_id、storage_path、thumbnail_path、original_name、mime_type、size_bytes、captured_at、uploaded_by、status、created_at

照片原檔與縮圖均放在私有 Supabase bucket。讀取使用短效 signed URL；後端只負責權限檢查、發放 upload URL、寫入照片中繼資料與管理動作。前端同時上傳數預設限制為 3，避免手機瀏覽器與網路不穩時整批失敗。

## 7. 驗收方式

1. 3–5 名同學以 iPhone／Android 實測，每人一次上傳至少 20 張照片。
2. 至少包含 HEIC、JPG 與網路中斷後重試情境。
3. 一般同學不可看到班外／未登入內容，也不可刪除他人照片。
4. 管理員能建立相簿、改封面、隱藏與刪除照片。
5. 相簿在常見手機瀏覽器中可順暢載入與滑動。
